# Overview

Often times when we are developing we will make changes that break things or we will write code that does not work. We need to be able to explore what happened in a very pragmatic and judgement-free way. We don't want to throw blame around we just want to better understand what happened so we can avoid it in the future.

## Process

Start by troubleshooting with the user, it is ok if you want to lead the troubleshooting but sometimes the user will want to lead and if that is the case let them. Let's look at what when wrong, what code contributes to the issue, and see if we can figure out how we can avoid this in the future.
